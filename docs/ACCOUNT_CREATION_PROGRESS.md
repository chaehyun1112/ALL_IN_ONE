# 계정 생성 연동 중간 저장 (2026-09-12)

- 관리자 생성 폼을 `POST /api/admin/users`에 연결했다. CSRF를 유지하고, 서버 성공 응답으로만 완료 창을 표시한다.
- 중복 제출 방지, 오류 표시, 생성 후 목록 재조회 및 완료 창을 닫을 때 임시 비밀번호 제거를 반영했다.
- Backend A의 상태값을 현재 DB와 같은 `APPROVED/INACTIVE`로 맞췄다. 병원·역할·병동 검증, BCrypt, 트랜잭션과 상태 변경 조건은 유지했다.
- 사용자 요청에 따라 실제 DB의 `emp_email` 컬럼을 제거했다. 적용한 SQL은 `db/migrations/20260912_drop_emp_email.sql`에 기록했다. 기존 회원가입 화면의 이메일 입력 부분도 제거했다.

## 사용자 요청으로 보류한 부분

- `MUST_CHANGE_PASSWORD` 컬럼은 추가하지 않았다.
- 최초 로그인 비밀번호 변경 강제 기능은 아직 연결하지 않았다.
- 계정 생성 SQL에는 Backend A의 `MUST_CHANGE_PASSWORD=TRUE`가 남아 있으므로, 현재 DB에서 계정 생성은 아직 성공할 수 없다.
- 실제 계정 생성이나 상태 변경 요청은 보내지 않았다. 이 커밋은 중간 작업 저장이며 계정 생성 기능 완료본이 아니다.
- 후속 작업은 사용자 결정 이후 진행한다. 이 문서는 이전 병합 기록 이후의 변경 상태를 설명하며 원본 Backend A 인수인계 문서는 보존한다.
